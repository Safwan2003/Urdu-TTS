================================================================
1. THE GOAL
================================================================
Production Urdu TTS voice = Piper `ur_PK-aegis_female-medium` (VITS, espeak `ur`,
22.05 kHz). It says plain Urdu well but mangles English loanwords inside Urdu
sentences ("keypad" -> "ki pat", "transaction"/"balance" muddy).

Fix = LoRA fine-tune: freeze 100% of the model, inject low-rank adapters into the
text encoder (~1% of params), train ONLY the adapters on a loanword-dense
corpus, fold them back into the weights at export -> a normal Piper ONNX with a
byte-identical phoneme_id_map. Because the base is frozen, plain Urdu cannot
regress. The whole pipeline is the Colab notebook.

3. WHAT THE ONNX->CKPT GRAFT LOOKS LIKE  (verified facts, 2026-09-04)
================================================================
Base ONNX: ur-aegis-female/ur_PK-aegis_female-medium.onnx  (63 MB, untracked,
  gitignored by *.onnx; also cached at
  ~/.cache/huggingface/hub/models--rhasspy--piper-voices/.../ur/ur_PK/aegis_female)
Config:    same file + ".json"  — num_symbols 256, phoneme_id_map (æ=39, ː=122),
  hop 256, sr 22050.  NO arch params in the json.

ARCH (piper "medium" == ModelAudioConfig.low_quality(), confirmed against
piper1-gpl config.py):
  spec_channels=513, inter_channels=192, hidden_channels=192, filter_channels=768,
  n_heads=2, n_layers=6, kernel_size=3, p_dropout=0.1,
  resblock="2", resblock_kernel_sizes=(3,5,7),
  resblock_dilation_sizes=((1,2),(2,6),(3,12)),
  upsample_rates=(8,8,4), upsample_initial_channel=256,
  upsample_kernel_sizes=(16,16,8), n_speakers=1, gin_channels=0, use_sdp=True

The ONNX has 350 initializers:
  - 296 NAMED  (enc_p.*, dp.*, flow.*, dec.conv_pre/conv_post) — map 1:1 to
    piper1-gpl SynthesizerTrn params by exact name. VERIFIED: all 296 are a
    BYTE-EXACT match to a generator param (0 name misses, 0 shape misses).
  - 53  OPAQUE `onnx::Conv_*` / `onnx::ConvTranspose_*` — weight-norm-folded
    convs whose names were dropped by constant-folding at export. **Route each
    one by its ONNX NODE NAME, never by order** — the exporter traces the flow
    in REVERSE, so the folded convs appear flows.6, flows.4, flows.2, flows.0,
    then dec (forward). Node name -> param, e.g.
        /flow/flows.6/enc/in_layers.0/Conv -> flow.flows.6.enc.in_layers.0.weight_v
        /dec/ups.0/ConvTranspose           -> dec.ups.0.weight_v
        /dec/resblocks.0/convs.1/Conv      -> dec.resblocks.0.convs.1.weight_v
    Then weight_v := W_onnx and weight_g := ||W_onnx|| over dims!=0, so
    torch._weight_norm(v,g,0) reproduces W_onnx.
    VERIFIED bit-exact end to end (see section 5).
  - 1  `onnx::Exp_9030` (shape 2,1): feeds node `/dp/flows.0/Exp`, i.e. it IS
    `-logs` of the SDP's ElementwiseAffine (dp.flows.0). So
        dp.flows.0.logs := -onnx::Exp_9030      (NOT -log(...) — that was a bug)
    dp.flows.0.m comes through NAMED and is exact.

NOT in the ONNX (training-only, don't affect inference; left at fresh random
init in the ckpt, loaded strict=False):
  - enc_q.*            (posterior encoder — training only)
  - dp.post_*          (dp.post_pre/post_proj/post_convs/post_flows — training only)
  - dp.flows.1.*       (first ConvFlow — the reverse SDP DROPS it:
        `flows = list(reversed(self.flows)); flows = flows[:-2] + [flows[-1]]`)
  - the MPD discriminator (model_d.*) — not in the ckpt at all (SynthesizerTrn
    has no discriminator). VitsModel inits it; opt_d trains it from scratch.
    NO Fasih / no other voice is grafted (user requirement). enc_q is handled
    by UNFREEZING it during training -- see section 5.

THE LoRA-NOISE PROBLEM AND ITS FIX (2026-09-04):
First Colab run -> base good, LoRA A/B = pure noise. In piper's VITS
training_step the KL term kl_loss(z_p, logs_q, m_p, logs_p) is the ONLY loss
with a gradient path to the frozen-base LoRA adapters (dec + enc_q frozen; the
mel/adv losses run through frozen modules). z_p/logs_q come from enc_q, which
the ONNX does not contain -> it was random and FROZEN -> garbage KL target ->
adapters learned garbage -> inference noise.

Rejected fix: graft enc_q + discriminator from the public Fasih (ur_PK-MALE)
ckpt. It made the noise worse (a confident *wrong* posterior), and the user
does not want any male-model weights in the pipeline.

ADOPTED fix (notebook cell 7): build the ckpt 100% from the Aegis ONNX (no
Fasih), then UNFREEZE enc_q and train it with the adapters. The mel loss runs
enc_q -> frozen female decoder, so enc_q quickly learns female latents; the KL
then gives the adapters a sane female target. enc_q + discriminator are
discarded at export -> shipped model is pure Aegis-female.
Verified locally: frozen base gets NO gradient during training (cannot drift);
enc_q + adapters both get finite gradients (tools/grad-check style).
Hyperparams: RANK 8, ALPHA 8, LR 1e-4, MAX_STEPS 1000.

ALSO FIXED: export_onnx.py got `dynamo=False,dynamo=False,` -> SyntaxError,
because the old `grep -q || sed` guard skipped a file already corrupted by an
earlier run. Cells 2 and 9 now run a regex repair:
